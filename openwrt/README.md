# The OpenWrt overlay

This directory is everything the ER-4 adds to a stock OpenWrt tree (the tag in [`versions`](../versions)): a target of its
own (`er4`) that builds on an external Oracle UEK7 kernel, the offload kernel module as a
package, the web UI package, and a few small patches for upstream packages. Nothing here is
copied into OpenWrt. [`setup.sh`](setup.sh) symlinks it into the checkout at `src/openwrt`.

The step-by-step build is in [docs/building.md](../docs/building.md). This page explains how
the pieces fit together.

## How a build fits together

```
configs/er4.fragment ─────────────► target/linux/er4/config-5.15   (tools/kernel-config.sh, committed)
src/uek7 (branch er4)  Oracle UEK7 5.15 + patches/uek7
src/uek7-openwrt  (worktree, er4) ► CONFIG_EXTERNAL_KERNEL_TREE     (created by setup.sh)
modules/ipfwd ────────────────────► package kmod-cavium-ip-offload
ui/dist (npm run build) ──────────► package er4-ui
                                     │  tools/build-openwrt.sh
                                     ▼
                     images/er4-openwrt-<date>-<commit>-k<kernel commit>.bin
```

1. **Kernel.** The target doesn't download or patch a kernel. `CONFIG_EXTERNAL_KERNEL_TREE`
   points OpenWrt at `src/uek7-openwrt`, a git worktree of `src/uek7` checked out at branch
   `er4` (Oracle's tag `$UEK7_TAG` from [`versions`](../versions) plus [`patches/uek7`](../patches/uek7)). OpenWrt
   builds in that tree in place, which is why it gets its own worktree: `tools/kernel-config.sh`
   (`O=build/uek7`) needs `src/uek7` itself to stay clean.
   `setup.sh` re-checks the worktree out at `er4` each time and stops if it has local changes,
   so kernel changes are committed on `er4` in `src/uek7`.
2. **Kernel config.** `config-5.15` is a complete config, generated by
   [`tools/kernel-config.sh`](../tools/kernel-config.sh) from `cavium_octeon_defconfig` plus
   [`configs/er4.fragment`](../configs/er4.fragment) (minus the initramfs options, which
   OpenWrt sets) and committed. Rerun the script after editing the fragment. The target Makefile replaces OpenWrt's
   `Kernel/Configure`: selected kmods still add their symbols (as `=m`) and `olddefconfig`
   fills in dependencies, but OpenWrt's `CONFIG_KERNEL_*` menu defaults are not applied,
   because they would turn off stack-protector-strong, LSMs and devtmpfs and turn on options
   the config deliberately leaves out. OpenWrt builds the kernel with its own toolchain
   (GCC 14, musl).
3. **Packages and image.** `setup.sh` writes `src/openwrt/.config` from [`diffconfig`](diffconfig)
   and [`tools/build-openwrt.sh`](../tools/build-openwrt.sh) builds `ui/`, runs `make`, and copies the initramfs kernel to `images/`.
   That one file is the whole system; it is installed from the web UI's firmware page
   ([docs/installing.md](../docs/installing.md)).

## What's here

| Path | What |
|---|---|
| `setup.sh` | Checks `src/` against [`versions`](../versions), links this overlay into `src/openwrt`, creates the kernel worktree, writes `.config` |
| `diffconfig` | Seeds `.config`: the ER-4 device, the external kernel tree, initramfs and ext4 images, the offload kmod, the web UI, WireGuard tools, strongSwan, 6in4; no `apk` |
| `target/linux/er4/` | Target "EdgeRouter 4 (UEK7, flow offload)": `Makefile` (kernel 5.15, own `Kernel/Configure`), `image/Makefile` (stripped ELF plus a board-name and build-ID trailer the firmware page checks), `config-5.15` (the full kernel config, generated by `tools/kernel-config.sh` and kept in git so config changes show up in a diff) |
| `target/linux/er4/base-files/` | Board files, below |
| `target/linux/generic/kernel-5.15` | Version stub OpenWrt requires for a 5.15 target. Only used for naming |
| `package/kernel/cavium-ip-offload/` | `kmod-cavium-ip-offload`, plus `/etc/init.d/offload` and `/etc/config/offload` |
| `package/utils/er4-ui/` | The web UI (`ui/dist`), its rpcd plugin `er4` (`files/er4.uc`) and ACL, a WAN health sampler, first-boot defaults, and the Tailscale service (`tailscale.init`, `er4-tailscale-fetch`: Tailscale's own build, fetched onto the eMMC) |
| `package/system/procd/patches/` | `900`: build against 5.15 kernel headers. `901`: ujail held signals too late, so a reload's SIGHUP could kill a jailed service (dnsmasq) for good |
| `package/system/rpcd/patches/` | No login while root has no password (stock rpcd accepts any password then) |
| `package/network/services/uhttpd/patches/` | Throttle failed logins per client address |

`setup.sh` links each patch in a `package/<dir>/<pkg>/patches` directory into the matching
package's `patches/` in the OpenWrt tree, so another upstream fix only needs a new file here.

### The offload module package

`kmod-cavium-ip-offload` builds [`modules/ipfwd`](../modules/ipfwd) against the target kernel.
Its `Build/Prepare` copies the module's **git-tracked** files (`git ls-files`) into the build
directory, so uncommitted new files are not picked up, and build output in the source tree
never leaks in. The init script loads the module at boot (`START=21`) and writes the options
from `/etc/config/offload` to `/proc/cavium/*`. Defaults: IPv4, IPv6 and VLAN offload on,
PPPoE off (not tested on this port), statistics on (the dashboard's fast-path hit rate; about
3 points of CPU at 790 kpps of 64-byte packets, well under 1 at normal packet sizes).

The kernel invalidates offloaded flows on firewall commits and route, address, link and
neighbour changes. After removing conntrack entries by hand (`conntrack -D/-F`), write `1` to
`/proc/cavium/invalidate`.

### Board files (`target/linux/er4/base-files/`)

- `lib/preinit/01_sysinfo`: U-Boot's device tree says `cavium,ubnt_e300` (shared by ER-4, 6P
  and 12) and the UEK kernel doesn't know the board, so name it `ubnt,edgerouter-4`, as
  upstream OpenWrt does.
- `lib/preinit/60_er4_persist`: the system runs from the initramfs; only `/etc` persists, as
  an overlay whose upper layer is `er4/etc` on the eMMC's second partition (next to the stock
  firmware's files, which stay untouched). Only when booted from eMMC: a TFTP netboot stays
  in RAM.
- `etc/board.d/01_network`: WAN `eth0`, LAN `eth1` as a plain port, `eth2`/`eth3` unassigned.
  There is no switch chip, so a bridge would be switched by the CPU, slowly and never offloaded.
  Port names follow the front panel (uek7 patch 0008): `eth0`–`eth2` RJ45, `eth3` the SFP cage.
- `etc/uci-defaults/90-er4-network`: packet steering off (it pinned each port's receive to one
  CPU), and undo the one-port `br-lan` that `config_generate` always creates.
- `etc/uci-defaults/91-er4-dns`: dnsmasq answers routed VPN clients too; the firewall decides.
- `usr/share/nftables.d/`: management (SSH, HTTP/S) and DNS are refused from the WAN before any
  user rule; an IPv6 reverse-path filter.
- `etc/sysctl.d/12-er4-conntrack.conf`: a connection-tracking table sized for 1 GB of RAM.
- `lib/preinit/79_move_config`, `lib/upgrade/platform.sh`: upstream OpenWrt octeon files.
  **`sysupgrade` is not supported on this target**: `platform.sh` still writes the upstream
  layout (kernel to `mmcblk0p1`, rootfs to `mmcblk0p2`), which would overwrite the stock
  firmware. Install images from the web UI.
